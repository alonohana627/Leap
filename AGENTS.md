# Notes for coding agents

Leap is a single-screen precision platformer campaign (four worlds of eight
rooms and a summit) built on GameLib (https://github.com/alonohana627/GameLib,
locally `C:\Users\user\GameLib`; a separate repository). It is the first
platformer of GameLib's run (`GameLib/GAME_SUGGESTIONS/05-leap.md` is its
spec).

## Ground rules

- Consume GameLib only through its CMake targets (`GameLib::core`,
  `GameLib::app`, ...) and public headers (`<gamelib/...>`). Never copy GameLib
  sources into this repository or include its `src/` files. Use what GameLib
  offers (its `FEATURES.md` at the pinned commit) instead of rewriting it.
- GameLib is pinned by full commit hash in `CMakeLists.txt` (`GIT_TAG`,
  `GIT_SHALLOW FALSE`). Bump it only together with a row in
  `docs/GAMELIB_REVISION.md`. GameLib keeps no backwards compatibility.
- GameLib is changed only to fix a bug that blocks the game (GameLib commit
  with a headless test first, then a re-pin). Generic code the game had to
  write itself is kept separable and reported as a P0 candidate for GameLib's
  `FEATURE_SUGGESTIONS.md`; this repository has no feature-suggestions file.
- Snake, Tetris, Pong, Breakout, Asteroids, Invaders and Minesweeper are
  read-only references.
- Every visual is generated by shaders (GameLib's built-in shapes or this
  game's `shaders/`). No image files. Every sound and the music are
  synthesized with GameLib's synth.
- `src/game` (rooms, rules, the session) links only `GameLib::core`: no
  window, GPU, audio or clock; deterministic for the per-tick input, so a
  recording of the input plays back exactly (the attract demo).
  Presentation, menus, sounds and saves live in `src/app`.
- **Games have no tests**: no unit tests, no test executables, no
  `GameLib::testing`. The only CTest entry is the template's smoke run
  (`--hidden --require-validation --frames 120`), which enforces zero Vulkan
  validation messages on the title screen.
- Zero compiler warnings, zero shader warnings (glslc `-Werror`), zero
  validation messages.
- Small Conventional Commits (`feat(game):`, `feat(app):`, `build:`,
  `docs:`) after each step that builds and runs. Stage files explicitly;
  never commit build output. Never rewrite history. Push `main` to origin
  after each commit.
- `FEATURES.md` lists what the game does today, verified by running it;
  update it in the same commit as each feature; never list planned work.
- Run the game and look at it after every visual change (GameLib's
  self-test switches plus the `win32-game-window-automation` skill for
  screenshots). Do not drive F11 in automated runs: fullscreen takes over the
  monitor.

## Skill suggestions

Keep `SKILL_SUGGESTIONS.md` up to date: at the start of a session list
`~/.claude/skills/` and move newly installed skills to "Already installed";
add or sharpen an entry (kebab-case name, one paragraph, a "Why") whenever a
task would have gone better with a missing skill. Mention changes in one line.

## Layout

```text
CMakeLists.txt, CMakePresets.json   project, GameLib pin, presets, the smoke run
src/game/                           rules -> GameLib::core: rooms.cpp (the campaign as text grids), rules.hpp (numbers, tuning, Input),
                                    session.cpp (one run: hero, hazards, crumbles, springs, saws, checkpoints, time)
src/main.cpp                        AppConfig and runMain
docs/GAMELIB_REVISION.md            the GameLib commit each change was validated with
```

## Commands

```powershell
cmake --preset debug           # configure (fetches GameLib from GitHub at the pinned commit)
cmake --build --preset debug
ctest --preset debug           # the smoke run (validation layer required)
build/debug/bin/leap.exe
```
